## Supervised synthetic-record procedure

The repository owner is the accountable test-record and recovery operator under this delegation. The person starting a later session performs the following checks before starting another session; Codex may execute them during an authorised task. This creates no promise of unattended background monitoring.

1. After normal exit, inspect the selected matter's `_ai-record` directory in the protected installation. Confirm the expected session JSONL exists and is nonempty, parses line by line, and has the correct session/matter association. Compute the selected archive and known same-session source transcript SHA-256 hashes privately and require equality before accepting filing. For example, assign only those two observed paths to `SESSION_ARCHIVE` and `SESSION_SOURCE`, then use `sha256sum "$SESSION_ARCHIVE" "$SESSION_SOURCE"` in the trusted terminal; never print their contents or search an authentication home indiscriminately. Retain the content-free comparison result and expected hash privately, and compare it again on any later copy or restore. If the source cannot be identified safely, record the filing gap and follow step 2. Keep content and account details private. Use the [runbook](../synthetic-container-checks.md) and [records recovery guidance](../operations.md) for failed or ambiguous filing.
2. If a file is missing, malformed, misbound or a copy failed, stop the next test session and record a content-free failure reference. Preserve source transcripts and existing copies. Investigate/retry through the documented recovery procedure; never infer a missing session identity or delete originals to clear the failure.
3. Preserve test records and encrypted backups throughout this evaluation. No automatic deletion or legal-hold claim is introduced; later cleanup requires an explicit owner disposition. The stored synthetic evidence is not a client records repository.
4. Accept that losing the original host and recovery key can make its encrypted synthetic backup unrecoverable. Existing key custody is sufficient for this limited evaluation; independent custody and a host-loss restore must precede confidential use. No key transfer or escrow is performed by this decision.

The actual observed SessionEnd and seven-check restore results satisfy the acceptance for this process. Routine checks for future sessions are operating duties, not missing acceptance tests.
